# Очистка и групповой fan-out — 2026-10-05

Финальная версия `c951bec` сохраняет индексы и ограниченные порции очистки. Объединённое SQL-чтение событий отклонено и отменено; HPKE-библиотека осталась прежней. Безусловного ускорения по CPU/задержкам не заявляем. Настройка через TOML оформлена отдельно в `148de04`: [русский справочник](reference.ru.md), [EN guide](configuration.md).

## Причины и исправления

До исправления диагностический тест 500/с × 300 с зафиксировал 31 отказ HTTP-admission и 0 отказов очереди записи. Лимит ожидания 100 мс истекал на фоне пауз тела транзакции 150–177 мс, совпадавших с минутной очисткой. DELETE сканировал растущие operations/events без индексов срока хранения и занимал единственное соединение записи. Миграция 2 атомарно добавляет индексы expires/created_at. Очистка удаляет максимум 256 строк за SQL-команду, уступает выполнение на 2 мс между порциями и продолжает backlog в пределах 20-секундного context; оставшееся может перейти на следующий минутный цикл. FULL, ограниченные очереди, HTTP 100 мс и Retry-After сохранены.

Диагностика после исправления: 0 отказов/ожидания HTTP и 0 отказов writer. Максимальная наблюдаемая slow-record пауза тела транзакции 11,75 мс против 175,91 мс до; commit 31,06 мс. Это выборки диагностического кольца, а не полные максимумы или основные замеры задержек. [До](benchmarks/retention-fanout/diagnostic-before.json), [после](benchmarks/retention-fanout/diagnostic-after.json). В первом обычном промежуточном soak осталось 20 ошибок 503; повторить их с временной шкалой не удалось, точная причина оставшихся пауз не подтверждена. Полное устранение всех отказов не заявляем.

Групповой CPU расходуется на X25519, системные вызовы и SQLite (_sqlite3VdbeExec 24,33% cumulative). Вложенные cumulative-проценты нельзя складывать. [Агрегат CPU](benchmarks/retention-fanout/diagnostic-cpu.txt). Стандартный HPKE не ускорил native-микротест и не принят: [числа](benchmarks/retention-fanout/hpke-experiment.json). Объединение двух чтений one-event replay сократило средний CPU на 3,4% относительно свежих контролей, но p99 групп вырос до 25,80/251,85 мс против 14,87/15,16 мс. Поэтому fast path отменён; [отклонённый patch](benchmarks/retention-fanout/rejected-replay-fusion.patch) сохранён. Unit/race сами по себе не подтверждали его производительность.

## Методика и ограничения

M5 Pro, 18 логических CPU, 48 GiB RAM, macOS 26.6.2. Docker Linux 6.12.76/aarch64: 18 vCPU и 8319213568 байт RAM; квота каждому контейнеру 4 CPU/8 GiB, VM общая с 31 другим контейнером. Локальный Docker volume; это не отдельный Linux/SSD-сервер. Loopback HTTP без TLS, trusted_proxy только в benchmark. Basic HPKE, storage AEAD, SQLite WAL/FULL, groups-only build, полный HTTP-ответ; постоянные device receipts генератор не отправляет.

В обоих тестах 2000 WebSocket, plaintext 256 байт. Soak: 1000 личных чатов, 500/с × 300 с. Группы: 10 чатов × 100 получателей,10/50/100/5 исходных сообщений/с по 20 с; остальные пользователи простаивают. Idle 10 с; перед каждой основной попыткой пауза 60 с, свежий контейнер/volume. Во время основных измерений сборки/тесты не выполнялись. Все сервисы запускаются последовательно; аналоги не перепрогонялись.

## Воспроизведение

```sh
python3 tools/scenarios/run.py --service qgramm --image qgramm:retention-final \
  --generator /absolute/private-work/generator-v2 --env-generator /absolute/private-work/env-generator \
  --users 2000 --chats 1000 --fanout 1 --payload-bytes 256 --steps 500:300s \
  --idle 10s --out /absolute/private-work/soak.json
# Group: use the frozen group generator; --chats 10 --fanout 100
# --steps 10:20s,50:20s,100:20s,5:20s
python3 tools/scenarios/summarize_followup.py --out /absolute/private-work/summary.json
```

Образ собран из неизменяемого архива исходников по [инструкции группового профиля](../tools/scenarios/README.md). Хеши идентифицируют сохранённые бинарники генераторов: будущая пересборка может отличаться даже при тех же исходниках и toolchain. Синтетические секреты тестовых устройств остаются приватными. Профилирование выполнялось отдельно с qg_bench_profile и timeline-only; pprof и реальное содержимое сообщений не публикуются.
