# Проверка WebRTC и внешнего TURN

`tools/webrtc` — отдельный интеграционный стенд, не поставляемый клиентский SDK. Его зависимости Pion находятся в собственных `go.mod`/`go.sum` и не добавляются в сервер.

Запуск из корня репозитория:

```sh
python3 tools/webrtc/run.py
```

Необходимы Python 3 и работающий Docker с доступом к реестру и Go/Alpine пакетам. Скрипт собирает реальный бинарный сервер через `cmd/qgramm-build` с конфигурацией `tools/webrtc/calls.toml`. В одном временном контейнере запускаются сервер и два независимых Pion PeerConnection; внешний по отношению к ним coturn работает в отдельном временном контейнере. Контейнеры соединяет изолированная Docker сеть. Порты на хост не публикуются. Секреты генерируются на каждый запуск, не выводятся и удаляются вместе с временной директорией. `finally` удаляет созданные контейнеры, сеть и собственный образ; общие базовые образы и другие сервисы не затрагиваются.

Стенд выполняет:

1. Создание пользователей, X25519 устройств и direct/basic чатов через management API; авторизацию устройств действительными короткими Ed25519 JWT.
2. Создание отдельных audio и video вызовов, принятие и завершение через calls API.
3. Передачу настоящих SDP offer/answer и ICE candidate через HPKE envelope API. Полный SDP после расшифровки получателем должен совпасть с исходным, включая DTLS fingerprint. HTTP JSON содержит шифротекст; SDP/ICE не передаются открытым текстом.
4. Установление ICE, DTLS и SRTP между независимыми peer connections.
5. Двустороннюю передачу Opus audio и VP8 video. FFmpeg генерирует действительные закодированные тон и кадры тестовой таблицы; получатель депакетизирует RTP и сравнивает каждый восстановленный sample с исходными закодированными sample. Требуется минимум пять совпавших кадров каждого вида в каждом направлении.
6. Повтор обоих видов вызова с `ICETransportPolicyRelay`. Каждый участник получает собственные credentials через `GET /v1/calls/turn`. У обоих peer connections выбранная пара должна состоять из relay/relay кандидатов — наличие TURN-конфигурации само по себе не считается успешной проверкой.

Тестовая HTTP связь сервера ограничена loopback внутри временного контейнера; рабочая установка требует TLS или доверенного proxy согласно основной конфигурации. Media остаётся защищённым DTLS-SRTP в обоих прогонах. В basic режиме доверенной стороной обработки SDP остаётся контейнер QGramm. Для E2EE аутентификация fingerprint должна выполняться клиентами через MLS; этот стенд такой MLS media сценарий не проверяет.

## Границы результата

Это проверка настоящего WebRTC транспорта между Pion peers и отдельного coturn, с настоящими закодированными аудио/видео кадрами. Это не проверка native browser, микрофона, камеры, воспроизведения звука, декодирования/отрисовки видео или UI: готовый UI/SDK в поставку не входит. Проверка осуществляется в частной Docker сети и не доказывает доступность публичного TURN, NAT traversal через провайдерские сети, TURN/TLS, TCP-only сети, production-развёртывание или browser compatibility.

Базовые API и media данные не подменяются заглушками. Генерируемые FFmpeg test media предназначены только для воспроизводимого acceptance.

## Наблюдение запуска

Проверено 2026-10-04 командой `python3 tools/webrtc/run.py`, exit 0. Runtime `linux/arm64`, Go 1.26.8, Pion/WebRTC v4.1.8, coturn 4.10.0-r0 и FFmpeg 8.1.2-r0. Сгенерированы 10 VP8 и 51 Opus исходных sample.

| Сценарий | Выбранная ICE пара у обоих peers | Audio sample к каждому peer | Video sample к каждому peer |
|---|---|---:|---:|
| Audio direct | host/host | 99 | — |
| Video direct | host/host | 99 | 19 |
| Audio forced TURN | relay/relay | 99 | — |
| Video forced TURN | relay/relay | 99 | 19 |

В обоих сценариях установлен DTLS-SRTP и проверена идентичность полученного SDP/fingerprint. Значения media счётчиков — фактические восстановленные sample, совпавшие с источником. При ошибке стенд возвращает ненулевой код и всё равно выполняет cleanup.

Источники API: [Pion RTP/WebRTC](https://github.com/pion/webrtc/tree/main/examples/rtp-to-webrtc), [coturn TURN REST authentication](https://github.com/coturn/coturn/blob/master/README.turnserver).
