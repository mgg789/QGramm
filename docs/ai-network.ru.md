# AI-сеть: первый этап

Именованный бот получает постоянные user/device ID, зашифрованные private identity
keys и отдельный зашифрованный контекст для каждого чата. Первый этап поддерживает BASIC личные и групповые
чаты. Старый API личного MLS AI-чата сохранён. Добавление новых именованных
ботов в MLS-группы пока отклоняется: для него нужен отдельный жизненный цикл
вступления, состояния участников и смены эпох.

## TOML

[Пример](../configs/ai-network.toml) задаёт endpoints и ботов. Порядок настроек:
глобальная `[ai]` → `[ai.endpoints.NAME]` → `[ai.bots.NAME]`. Явное `false`
переопределяет наследуемое значение; нулевые числовые лимиты отклоняются.
Если глобальная модель не задана, требуется корректный `default_bot`.

Endpoint содержит provider, URL, модель, имя переменной с ключом, режим auth,
разрешение приватных адресов, streaming, capabilities и лимиты. Бот задаёт
endpoint, статический system prompt, инструменты и переопределения лимитов.
Текущие capabilities — `basic_text` и `tool`; это описание настроенного
адаптера, а не результат автоматической проверки модели. Мультимодальность
и structured output требуют следующих контрактов и сейчас не объявляются.

`auth="bearer"` читает ключ из окружения при вызове. Явное `auth="none"`
требует `allow_private=true` и отсутствия key_env: так подключается локальный
OpenAI-compatible сервер без ключа. Это доверенный endpoint, куда приходит
plaintext. Redirects и proxy из окружения отключены; DNS разрешается один раз,
соединение устанавливается только с проверенными адресами.

`features.ai_streaming=true` добавляет build tag `qg_ai_streaming`. Отдельный
бот может отключить streaming. Полное исключение модуля требует пересборки:
без него отсутствуют SSE-реализации, progress-маршруты, таблицы и cleanup.
Секретные значения не попадают в TOML, manifest, задания и логи.

## Постоянные участники и явный запуск

Backend вызывает `POST /management/v1/ai/agents` с телом
`{"bot_name":"assistant","user_id":"ai-assistant","tools":[]}`. `user_id`
и `tools` необязательны: без `user_id` сервер создаёт постоянный AI user, без
`tools` используется набор профиля бота. Полученного пользователя
можно использовать в обычном управлении чатами. Затем AI-сессия подключается
через `POST /management/v1/ai/agents/{agent}/chats/{chat}` с allowlist `tools`.
Инструменты TOML-профиля — верхняя граница разрешений этой сессии.

Один бот обслуживает несколько чатов, несколько ботов могут участвовать в
группе. Личный чат сохраняет лимит двух участников. Действуют обычные ACL,
can_send, disable пользователя и revoke устройства. Контексты разных ботов
и чатов не смешиваются. Endpoint и bot разрешаются по актуальному TOML в
момент запуска задания; зашифрованный профиль создания хранится для
непрерывности identity и аудита.

Пользователь сначала отправляет обычное зашифрованное сообщение, затем явно
адресует его ботам через `POST /v1/chats/{chat}/ai/tasks`:

```json
{"message_id":"accepted-message-id","agents":["ai-assistant","ai-reviewer"]}
```

Проверяется авторство пользователя/устройства. Пара `(message_id,agent_id)`
дедуплицируется; одновременно исполняется одно задание на бот/чат. Ответ AI
сам по себе не запускает другого AI. Метаданные задания доступны через
`GET /v1/chats/{chat}/ai/tasks/{task}`, а список возвращает последние 100 задач.
Отмена через `DELETE /v1/chats/{chat}/ai/tasks/{task}` доступна и без модуля
streaming. Права проверяются перед исполнением
и финальной публикацией. Глобальное удаление исходника сбрасывает связанный
контекст и блокирует поздние ответы. После рестарта активные внешние запросы
становятся `uncertain`, автоматического повторного платного вызова нет.

## Streaming и восстановление

SSE OpenAI-compatible и Anthropic обрабатывается по мере получения. Обрыв,
невалидный ответ и превышение лимита не превращаются в успешный финальный
результат. Дельты tool calls не являются разрешением на запуск инструмента.

Сохранение части создаёт событие `ai.progress.available` с job ID, cursor
и kind, без текста и аргументов. Ciphertext выдаётся через
`GET /v1/chats/{chat}/ai/jobs/{job}/progress?after=0`, максимум 200 частей.
Для reconnect используются журнал событий и последний cursor части.

В BASIC часть шифруется на диске и оборачивается HPKE для устройства читателя.
В старом личном E2EE-чате часть — MLS ciphertext; состояние ratchet, часть
и событие фиксируются атомарно. Финальное сообщение использует актуальное
сохранённое состояние. Binding обычный: chat/sender/device/operation_id;
operation_id имеет вид `ai-progress-{job}-{chunk}`.

Расшифрованная часть — JSON. `text.delta` содержит `text`, `tool.started` —
`index/id/name`, `tool.arguments.delta` — `index/arguments`. Части являются
предпросмотром: завершение подтверждают `succeeded` и финальное обычное
сообщение. Частичный результат может завершиться failed/uncertain/cancelled.

Первая текстовая дельта фиксируется сразу. Последующие объединяются до 4 КиБ,
при следующей дельте через 25 мс, смене kind либо завершении провайдера;
отдельного timer worker на стрим нет. Лимит — 4096 частей и 2 МиБ сохранённых
данных на задание. Retention следует event_retention_hours, cleanup ограничен
порциями. Истёкший cursor возвращает 410, cursor впереди — 400. Завершённый
ответ можно восстановить из истории сообщений. Чтение проверяет текущие ACL
и доступность исходника по моменту вступления.

Автор задания или администратор вызывает
`POST /v1/chats/{chat}/ai/jobs/{job}/cancel`. Сначала фиксируется отмена,
затем прерывается локальный активный запрос. Поздняя публикация блокируется;
уже отправленный внешний эффект или расходы провайдера отмена не откатывает.

## Следующие этапы

Второй этап: подписанные системные разрешения, подтверждение инструментов,
счётчики/бюджеты и события выхода plaintext из контура. Третий: micro-safer
для LLM/tools и scoped file/RAG/GraphRAG с явным владением ключами. Эти
возможности пока являются планом. Модель и поиск работают с plaintext внутри
доверенного узла; шифрование сети не защищает от компрометации этого хоста.
Независимые MLS interop и криптоаудит отделены от локальных тестов.
